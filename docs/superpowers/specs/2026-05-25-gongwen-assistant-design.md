## 1. 产品定位

公文助手是面向大型企业、集团、政府及事业单位的 AI 公文起草与套版工作台。它不是泛写作工具，也不是完整 OA 系统；MVP 目标是先跑通严肃公文生产的核心闭环：

选择文种 -> 填写字段 -> 上传 Word/PDF 材料 -> AI 生成提纲 -> 逐段生成正文 -> Word 版式预览分块编辑 -> 基础质检 -> 套用 Word 模板导出 `.docx`

MVP 采用私有化单单位 Web 应用形态。长期预留 SaaS、多租户、审核流、部门权限、知识库、OA/WPS/Word 插件和私有化模型适配。

## 2. 目标用户

MVP 只暴露两个角色：

- 起草人：填写公文信息、上传参考材料、生成草稿、分块修改、质检、导出 Word。
- 模板管理员：上传 Word 模板、解析占位符、配置文种字段和结构。

后续预留但不在 MVP 完整实现：

- 审核人：审阅草稿、提出意见、通过或驳回。
- 系统管理员：管理用户、权限、组织、审计日志和系统配置。

## 3. MVP 范围

MVP 内置三个高频文种：

- 通知
- 请示
- 报告

MVP 包含：

- 三栏公文起草工作台
- Word 风格版式预览
- 分块编辑标题、主送、正文、附件、落款、日期
- Word/PDF 材料上传和文本提取
- AI 提纲生成和逐段正文生成
- 选中段落的 AI 改写、扩写、压缩、正式化
- 基础质检和导出前检查
- `.docx` 模板上传、占位符解析、字段配置
- `.docx` 导出
- 登录和基础权限
- PostgreSQL 持久化
- 云端模型 API 接入，架构预留私有化模型

MVP 不包含：

- 完整审核流界面
- 多单位 SaaS 运营后台
- 完整在线 Word 编辑器
- PDF 导出
- 图片/扫描件 OCR
- 复杂格式细检
- 涉密/越权完整风控
- 部门级知识库权限过滤
- OA/WPS/Word 插件

## 4. UI 与交互方向

UI 采用 Anthropic-inspired 风格：克制、清晰、低噪声、专业可信。适合政企和集团用户长时间使用。

视觉要求：

- 温和中性色、米白或暖灰背景、深色正文、低饱和强调色。
- 避免花哨科技感、强渐变、大面积高饱和色。
- AI 状态、质检风险、成功、警告、错误使用语义色区分，但整体保持克制。
- 工作台优先桌面端体验，移动端至少可用。
- 文本层级清楚，不溢出、不遮挡、不依赖装饰表达信息。

工作台布局：

- 左侧：文种、模板、字段表单、材料上传。
- 中间：Word 风格版式预览和分块编辑。
- 右侧：AI 建议、基础质检、导出前检查、导出操作。

AI 交互状态必须可见：

- 初次加载骨架屏
- 生成中状态
- 长任务仍在处理提示
- 取消生成
- 失败提示
- 重试
- 空状态
- 权限不足状态

## 5. 功能模块

### 5.1 公文起草工作台

起草人通过工作台完成公文生产闭环。

能力：

- 选择通知、请示、报告。
- 选择可用模板。
- 填写结构化字段。
- 上传 Word/PDF 材料。
- 触发 AI 生成提纲和正文。
- 在 Word 风格预览中分块修改。
- 查看 AI 建议和质检清单。
- 套用模板并导出 `.docx`。

### 5.2 AI 生成模块

AI 采用“两段式 + 局部操作”。

第一步：生成提纲。

- 输入：文种、模板字段、用户填写内容、上传材料摘要。
- 输出：标题建议、正文结构、段落要点、缺失信息提示。
- 用户可确认或调整。

第二步：逐段生成正文。

- 按确认后的结构生成正文块。
- 每个正文块保留来源上下文和生成 trace。
- 单段失败可单段重试，不必重生成全文。

局部操作：

- 正式化
- 压缩
- 扩写
- 改写
- 补充要求

局部操作结果先作为建议出现，用户确认后替换原文。

### 5.3 模板管理模块

模板管理员负责公文模板配置。

能力：

- 上传 `.docx` 模板。
- 解析 `{{标题}}`、`{{正文}}`、`{{落款}}` 等占位符。
- 配置字段含义、是否必填、字段类型、默认值和排序。
- 配置文种结构。
- 绑定模板到一个或多个文种。
- 启用、停用模板。
- 模板支持版本号。

### 5.4 材料管理模块

MVP 支持 Word 和 PDF。

能力：

- 上传 Word/PDF。
- 限制文件类型和大小。
- 提取材料文本。
- 将材料文本作为本次生成上下文。
- 记录材料来源，后续用于依据提示。

暂不做图片 OCR。

### 5.5 基础质检模块

MVP 先做基础规则检查和语言风格检查，预留格式细检与风险检查。

检查项：

- 必填字段是否完整。
- 模板占位符是否全部映射和填充。
- 标题、主送、正文、附件、落款、日期是否完整。
- 通知、请示、报告是否符合基本结构。
- 表达是否口语化、冗余、语气不当或逻辑断裂。
- 导出前是否满足生成 Word 的条件。

后续增强：

- 字体字号、页边距、标题层级、编号格式细检。
- 涉密、越权、敏感表达和依据不足风险提示。

### 5.6 文档导出模块

MVP 只导出 `.docx`。

规则：

- 草稿内容以结构化块保存。
- 导出时将字段和正文块填入 Word 模板。
- 导出前必须通过基础检查。
- 导出记录保存导出人、时间、模板版本和文件路径。
- 最终版式以 Word 模板导出结果为准。

PDF 导出作为第二阶段增强。

## 6. 技术架构

采用 Java 后端优先的前后端分离架构。

- 前端：React + TypeScript
- 后端：Spring Boot
- 数据库：PostgreSQL
- 文件存储：本地存储抽象，后续可切 MinIO
- AI 接入：模型适配层，MVP 使用云端大模型 API
- 文档处理：后端负责 `.docx` 模板解析、占位符填充、导出
- 部署：单单位私有化 Web 应用

关键边界：

- 模型调用集中在 ModelAdapter，不散落在业务代码里。
- Prompt 集中管理，并按文种和任务版本化。
- 材料解析、模板填充、AI 生成、质检拆成独立服务。
- 文件上传、模型调用、导出操作必须有日志和错误状态。
- 删除模板、批量操作、未来审核通过等高风险操作要确认和审计。

## 7. 数据模型

核心实体：

- User：用户账号、姓名、角色、状态。
- Role / Permission：RBAC 预留，MVP 启用起草人和模板管理员。
- DocumentType：文种，内置通知、请示、报告，后续支持自定义。
- Template：Word 模板文件、版本、适用文种、状态。
- TemplateField：模板占位符、字段名、字段类型、是否必填、默认值、排序。
- Draft：公文草稿，标题、文种、模板、状态、创建人、更新时间。
- DraftBlock：结构化内容块，如标题、主送、正文段落、附件、落款、日期。
- Material：上传材料，文件类型、提取文本、来源、所属草稿。
- AiGenerationTrace：AI 请求、任务类型、模型、耗时、状态、错误摘要。
- QualityCheckResult：字段检查、结构检查、语言建议、导出前检查结果。
- ExportRecord：导出文件、导出人、导出时间、模板版本。

PostgreSQL 使用原则：

- 使用关系表保存权限、模板、草稿、材料和导出记录。
- 使用 JSONB 保存适合半结构化的数据，例如草稿块快照、质检结果、AI trace 元数据。
- 后续知识库/RAG 可基于 PostgreSQL 扩展，必要时再接专门向量库。

预留字段：

- tenant_id：未来多单位隔离。
- department_id：未来部门权限。
- review_status：未来审核流。
- version_no：未来版本留痕。

## 8. 权限与安全

MVP 采用 RBAC 预留设计，界面只暴露起草人和模板管理员。

起草人权限：

- 创建、编辑自己的草稿。
- 上传本草稿材料。
- 调用生成、质检、导出。
- 查看自己的导出记录。

模板管理员权限：

- 上传和管理模板。
- 配置文种字段结构。
- 启用、停用模板。
- 查看模板解析结果。

安全默认要求：

- 登录后才能访问系统。
- 模板、材料、导出文件下载必须校验权限。
- 文件上传限制类型和大小。
- SQL 查询必须参数化。
- HTML/Markdown 渲染必须消毒。
- AI 日志不保存完整敏感正文，只记录摘要、状态和 trace id。
- 模板删除、草稿删除等高风险操作后续要有确认和审计。

功能验收：

- 支持通知、请示、报告三个文种。
- 起草人完成选择文种、填写字段、上传 Word/PDF、生成提纲、生成正文、分块编辑、质检、导出 Word。
- 模板管理员完成上传 Word 模板、解析占位符、配置字段和文种结构。
- 导出的 `.docx` 可以正常打开，基础版式符合模板。

质量验收：

- 必填字段和占位符缺失能被检查出来。
- AI 生成内容结构完整、语气正式、无明显口语化。
- 通知、请示、报告分别符合基本文种结构。
- 从填写信息到导出 Word 的时间目标为 5-10 分钟。

安全验收：

- 起草人只能访问自己的草稿和材料。
- 模板管理能力仅模板管理员可用。
- 文件上传限制类型和大小。
- AI 日志不保存完整敏感正文。
- 模板、材料、导出文件下载都有权限校验。

UI/体验验收：

- 使用三栏工作台。
- 符合 Anthropic-inspired 克制配色和低噪声界面。
- 有加载、生成中、失败、重试、取消、空状态。
- Word 预览不乱码、不溢出，文本层级清楚。
